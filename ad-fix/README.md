# deploy_and_fix_ad.sh — диагностика и исправление интеграции с Active Directory на ALT Linux

## 1. Постановка задачи

В корпоративной среде на рабочих станциях ALT Linux после обновления системы или пакетов, отвечающих за аутентификацию через Active Directory (SSSD/Winbind), могут возникать следующие проблемы:

- Неверные права доступа на файле `/etc/sssd/sssd.conf` (должны быть `600`).
- Недостаточный диапазон ID (`id_max`) в конфигурации SSSD, что приводит к ошибкам `getpwuid(200000) failed` и невозможности разрешить SID в UNIX-UID.
- Устаревший кэш SSSD/Winbind, из-за чего изменения в Active Directory не отображаются на клиенте.
- Отсутствие актуальных списков пакетов перед установкой ПО.

Требования:

- Автоматическое исправление без участия администратора (кроме ввода пароля при необходимости).
- Безопасность: резервное копирование конфигурационных файлов, атомарное изменение, проверка прав.
- Надёжность: повторные попытки запуска служб, очистка кэша, перезапуск.

## 2. Архитектура решения

Скрипт `deploy_and_fix_ad.sh` выполняет два основных блока:

1. **Обновление списков пакетов** (`apt-get update`) — выполняется в начале, ошибка прерывает выполнение.
2. **Исправление SSSD/Winbind** (в зависимости от определённого бэкенда):
   - Проверка наличия конфигурационного файла (`/etc/sssd/sssd.conf` или `/etc/samba/smb.conf`).
   - Создание резервной копии в `/var/backups/ad-fix-<timestamp>/`.
   - Установка прав `600` на `sssd.conf` (требование SSSD).
   - Проверка и увеличение `id_max` до 200000 (если текущее значение меньше).
   - Включение и запуск службы (`systemctl enable --now sssd` или `winbind`).
   - Очистка кэша (`sss_cache -E` или `net cache flush`).
   - Перезапуск службы для применения изменений.

## 3. Ключевые технические решения

### 3.1. Установка прав 600 на sssd.conf
SSSD требует, чтобы файл конфигурации был доступен только владельцу (root), так как в нём могут содержаться учётные данные для подключения к LDAP/AD. Установка прав `600` предотвращает чтение конфигурации другими пользователями и соответствует рекомендациям безопасности.

### 3.2. Увеличение id_max до 200000
В ALT Linux и других дистрибутивах диапазон UID для доменных пользователей может достигать 200000. Чтобы избежать ошибок `getpwuid(200000)`, необходимо, чтобы `id_max` в SSSD был не меньше максимального используемого UID. Скрипт автоматически увеличивает его до 200000.

### 3.3. Очистка кэша SSSD
Команда `sss_cache -E` полностью очищает кэш пользователей, групп и других объектов. Это полезно после изменения настроек и для принудительного обновления данных из AD. После очистки служба перезапускается.

### 3.4. Атомарное изменение конфигурации
Изменение параметра `id_max` выполняется через `sed -i`, но предварительно файл копируется в резервную копию. Это гарантирует возможность отката при сбое.

## 4. Установка и настройка

### Предварительные условия
- Установлен пакет `sssd` (или `task-auth-ad-sssd`) или `samba-winbind`.
- Настроен `/etc/sssd/sssd.conf` для домена (или будет настроен скриптом).
- Служба sssd остановлена или работает с ошибками.

7. Заключение

Скрипт автоматически восстанавливает работоспособность аутентификации через Active Directory на ALT Linux, исправляя критические параметры (права, id_max, кэш). Использование резервного копирования и безопасных методов изменения конфигурации минимизирует риски. Рекомендуется включать скрипт в процессы развёртывания и регулярного обслуживания рабочих станций.
