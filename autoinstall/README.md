# autoinstall.sh — автоматизация развертывания рабочих станций ALT Linux

## 1. Постановка задачи

### Бизнес-контекст
Внедрение новых рабочих станций в ИТ-инфраструктуру компании и приведение существующих машин к единому стандарту требовало значительного времени и ручного вмешательства. Процесс сопровождался человеческими ошибками, дрейфом конфигураций и задержками в подключении к системам мониторинга и инвентаризации.

### Решаемые проблемы
- Отсутствие единообразия в установленном ПО.
- Ручная настройка агентов мониторинга и инвентаризации.
- Сложность развертывания системы проверки уязвимостей.
- Низкая скорость и высокий процент ошибок при ручной установке.

### Требования
- **Автоматизация:** полная установка и настройка рабочей станции за один запуск скрипта.
- **Безопасность:** автоматическое обновление системы и сканирование OVAL-уязвимостей.
- **Масштабируемость:** возможность массового развертывания.
- **Отказоустойчивость:** устойчивость к ошибкам репозиториев, конфликтам пакетов и некорректным конфигурациям.
- **Идемпотентность:** повторный запуск не должен разрушать уже настроенную систему и должен пропускать выполненные шаги.

## 2. Архитектура решения

### Компоненты
- **Целевая ОС:** ALT Linux (p10/c10f2).
- **Язык:** Bash (`set -euo pipefail`, `trap` для диагностики).
- **Управление пакетами:** APT/RPM.
- **Службы:** Zabbix Agent, GLPI Agent, CUPS, UrBackup Client, Dr.Web.
- **Сканирование:** OVAL через `openscap`.

### Схема взаимодействия
- **Репозитории:** создание файлов в `/etc/apt/sources.list.d/`, комментирование CD-ROM.
- **Установка ПО:** `apt-get install -y`.
- **GLPI:** модификация `/etc/glpi-agent/agent.cfg`, запуск службы.
- **Zabbix:** настройка `zabbix_agentd.conf`, добавление `UserParameter` в `/etc/zabbix/zabbix_agentd.conf.d/oval.conf`.
- **OVAL:** база в `/var/lib/scanoval/data/`, скрипты `scan_oval_auto.sh` и `get_oval_vuln_count.sh`, Systemd Timer.

### Режимы работы
- **Интерактивный:** запуск с терминала, прогресс-бар, запрос на удаление папки установки.
- **Автоматический:** через Systemd Timer (замена Cron).

## 3. Ключевые технические решения

1. **`set -euo pipefail` и `trap`** — немедленное завершение при ошибках и точная диагностика (строка, код, команда).
2. **Фикс CD-ROM** — комментирование строк с CD-ROM для исключения ошибок `apt-get update`.
3. **Идемпотентность (`ensure_config_param`)** — проверка соответствия параметра эталону, замена или добавление при расхождении.
4. **Исправление «склейки» строк в Zabbix** — поиск через `grep -qE` и разделение через `sed -i -E`.
5. **Systemd Timer с `Persistent=true`** — запуск задачи при следующем включении, если компьютер был выключен.
6. **Устойчивость к конфликтам пакетов** — функция `fix_duplicate_packages` анализирует ошибки, удаляет лишние версии через `rpm -e --allmatches --nodeps`.

## 4. Установка и настройка

### Необходимые компоненты
- ALT Linux, права root.
- Файл базы OVAL: `Alt10VulnsOVAL.xml`.
- Установщик Dr.Web (`.run`), если требуется.

### Настройка под среду
Переменные в начале скрипта:
- `GLPI_SERVER`
- `ZABBIX_SERVER`
- `ZABBIX_HOST_METADATA`
- `PACKAGES`

### Запуск
```bash
chmod +x autoinstall.sh
sudo ./autoinstall.sh
```

## 6. Устранение проблем

| Проблема | Причина | Решение |
|----------|---------|---------|
| `Unsupported item key` в Zabbix | Скрипт не выполняется, конфиг не подхватывается, или «склейка» строк | Проверьте `UserParameter=oval.vuln.count`. Выполните `sudo -u zabbix /usr/local/bin/get_oval_vuln_count.sh` |
| `E: Failed to fetch cdrom://` | CD-ROM не закомментирован | Проверьте `/etc/apt/sources.list.d/` |
| `E: Ошибка во время исполнения транзакции` | Конфликт версий пакетов | `rpm -e --allmatches --nodeps <package>` |
| Скрипт остановился с ошибкой | Сработал `trap` | Вывод укажет точную строку и команду |

## 7. Глубокая интеграция с Zabbix: конфигурация и работа

### 7.1. Архитектура мониторинга
- **Zabbix Server** (например, 192.168.1.10) – центральный сервер, собирает данные, хранит историю, генерирует алерты.
- **Zabbix Agent** – демон на каждой рабочей станции, выполняет команды по запросу сервера или отправляет данные сам.

### 7.2. Что настраивает скрипт на клиенте
- `Server` – IP-адрес Zabbix Server (192.168.1.10).
- `ServerActive` – IP-адрес Zabbix Server.
- `Hostname` – техническое имя машины (например, `hostname.example.com`).
- `HostMetadata` – ключ авторегистрации (например, `alt.autoreg`).
- `Include` – путь к директории конфигов (`/etc/zabbix/zabbix_agentd.conf.d/*.conf`).
- `UserParameter=oval.vuln.count,...` – кастомный параметр для выполнения скрипта `/usr/local/bin/get_oval_vuln_count.sh`.

### 7.3. Процесс авторегистрации
1. Скрипт запускает `zabbix_agentd`.
2. Агент отправляет на сервер (порт 10051) свой `Hostname` и `HostMetadata`.
3. На сервере Zabbix заранее создано действие авторегистрации с условием `Host metadata contains alt.autoreg`.
4. Сервер автоматически создает хост, добавляет в группу и привязывает шаблон.
5. Через 1–2 минуты хост появляется в списке, начинается сбор данных.

### 7.4. Жизненный цикл метрики OVAL
- **Фаза сканирования (раз в 30 дней):** Systemd Timer запускает `scan_oval_auto.sh`, который обновляет систему и выполняет `oscap oval eval`. Результат записывается в `/var/log/scanoval/vuln_count.txt`.
- **Фаза опроса (раз в 1 минуту):** Zabbix Server инициирует проверку `oval.vuln.count`. Агент выполняет `get_oval_vuln_count.sh`, который читает файл и выводит число в stdout. Значение сохраняется в базе истории.

### 7.5. Триггеры и оповещения
- **OVAL vulnerabilities found** – выражение `last(oval.vuln.count)>0`, высокий приоритет.
- **OVAL vulnerabilities cleared** – выражение `last(...)=0 and last(...,#1)>0`, информационный.

### 7.6. Визуализация данных
- `Мониторинг → Последние данные` – таблица с текущим числом уязвимостей по машинам.
- Виджет «Топ узлов сети» – сортировка по количеству уязвимостей.
- `Мониторинг → Проблемы` – активные триггеры.

### 7.7. Требования к серверной части
Администратор должен один раз настроить:
- Действие авторегистрации.
- Шаблон с элементом `oval.vuln.count` и триггерами.
- Права на чтение для группы пользователей.

## 8. Внешняя конфигурация (DevOps Best Practice)
Рекомендуется выносить настройки в отдельный файл `install.conf` и подгружать через `source`.

Пример `install.conf`:
```bash
GLPI_SERVER="http://192.168.1.20/glpi/plugins/glpiinventory/"
ZABBIX_SERVER="192.168.1.10"
ZABBIX_HOST_METADATA="alt.autoreg"
OVAL_DATA_SOURCE="/root/autoinstall/Alt10VulnsOVAL.xml"
PACKAGES=(yandex-browser-stable vino-mate glpi-agent ...)
```

В скрипте:
```bash
if [[ -f "/etc/autoinstall/install.conf" ]]; then
    source /etc/autoinstall/install.conf
else
    echo "Файл конфигурации не найден! Используются значения по умолчанию."
fi
```

## 9. Логирование и аудит
Для полного логирования запуска:
```bash
sudo ./autoinstall.sh 2>&1 | tee /var/log/autoinstall_$(date +%Y%m%d_%H%M%S).log
```

Или встроить в скрипт:
```bash
LOG_FILE="/var/log/autoinstall.log"
exec > >(tee -a "$LOG_FILE") 2>&1
```

## 10. Модель безопасности и риски
- **Запуск от root:** скрипт должен быть доступен только администраторам (`chmod 700`).
- **Риск цепочки поставок:** проверять контрольную сумму (SHA-256) файла Dr.Web перед запуском.
- **Сетевые порты:** открывать порт 10050 только для сервера Zabbix, закрыть на внешнем периметре.
- **Права на файл `vuln_count.txt`:** доступ на чтение пользователю `zabbix`, запрет записи обычным пользователям.

## 11. Откат и восстановление
- Скрипт идемпотентен, повторный запуск безопасен.
- Очистка временных файлов: `rm -f /tmp/drweb_installer_*.run`.
- Бэкапы конфигов: `agent.cfg.bak.*`, `sources.list.bak.*`. Откат: `cp /etc/glpi-agent/agent.cfg.bak.* /etc/glpi-agent/agent.cfg`.

## 12. Тестирование и внедрение
1. **Staging-тест** на виртуальной машине.
2. **Пилотная группа** из 2–3 машин.
3. **Массовое развертывание** через `scp` или `rsync`.
4. **Версионирование:** Git-теги для стабильных версий (например, `v1.2.0`).

## 13. Расширение функционала
- **Новый пакет:** добавить в массив `PACKAGES` и в секцию `verify_installation`.
- **Изменение расписания:** правка `/etc/systemd/system/scan-oval.timer`.
- **Удаление программы:** убрать из массива `PACKAGES`.

## 14. Заключение
Скрипт решает проблемы времени установки, дрейфа конфигураций, отказоустойчивости при обновлениях и некорректной работы с репозиториями. Рекомендуется хранить его в корпоративном Git-репозитории.
